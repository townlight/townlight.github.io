Townlight Windows beta support

Current Windows release: 1.9.3.2. Download the MSI, verify it against the checksums, and review acceptance and limits. The exact signed MSI passed fresh acceptance after a fixture-only correction, with no rebuild, and passed direct upgrade from 1.9.3.1 and lifecycle checks. See the first-run guide, IT specifications, Records workflow, staff roles, backup and recovery, and verified workflows and limits. Acceptance does not claim all modules were retested; Windows 1.9.3.1 remains documented separately as a historical release.

To upgrade from Windows 1.9.3.1, back up city data and settings, close Townlight, run the signed 1.9.3.2 MSI, then reopen using the same Windows account and profile. Direct upgrade from 1.9.3.1 passed; earlier versions are not covered by this direct-upgrade result, so see acceptance.

Installation and recovery

Fresh installation. Follow first-run setup with a new Townlight profile. The 1.9.3.2 GitHub release acceptance defines the installation scope and limits for the current release; it does not claim all modules were retested.

Windows 1.9.1.1 was the previous signed public beta. Its release and acceptance results remain version-specific.

Historical Windows 1.9.1.1 upgrade note (from 1.9.0.1). Back up your city data and settings in Townlight and close the app before running the signed MSI. Reopen Townlight under the same Windows account with your existing profile. If Station shows as unconfigured, open Settings → Modules → Townlight Station and select Set up meeting recording. After restoring a backup, start the services before checking your records. The acceptance summary identifies the 1.9.0.1 upgrade run on the earlier signed candidate. The separate verified 1.8.2.1 upgrade ended at 1.9.0.1. A direct upgrade from 1.8.2.1 or older to 1.9.1.1 has no test result; Windows 1.9.2.1 has no direct-upgrade acceptance from any earlier MSI.

Follow the backup, recovery and maintenance guidance. Preserve existing data and backups. Do not rename or delete the compatibility profile directory %LOCALAPPDATA%\CivicSuite to work around a setup problem.

Verify the downloaded MSI against the Windows 1.9.3.2 release checksums and the GitHub release acceptance. Use the exact release link. The GitHub release acceptance defines installed checks and limits.

For setup problems, consult troubleshooting before filing an installer issue. Do not remove a database or existing profile as a troubleshooting shortcut.

See the Windows staff workflow guide for roles and cross-module staff workflows.

If you cannot identify the owning product, start with the Suite issue tracker. For questions and evaluation feedback, use Townlight Discussions.

What to include

  • Installed version (1.9.3.2) and Windows version.
  • The selected products/profile and whether this was a fresh installation.
  • Steps to reproduce, what you expected and what happened.
  • Redacted error messages, logs or screenshots, using synthetic data where possible.

Do not attach resident information, credentials, tokens, database copies or unredacted backups to public issues. Do not post security vulnerabilities in public issues: follow the security policy and report privately to the affected repository.

Separate deployments and evidence

The resident portal requires separate deployment. The Windows installer does not provision a public website. Standalone CivicCast remains a separate product. The current Windows acceptance uses synthetic data and does not establish a live city deployment or physical broadcast acceptance. Follow each product guide for its supported workflow.
