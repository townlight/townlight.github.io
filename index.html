Why Townlight exists

Public work should not require surrendering public control.

Municipal teams face cloud lock-in, recurring seat costs, scattered workflows, and AI tools that move sensitive material beyond the city's boundary.

Townlight takes a narrower path: local-first software for the high-friction work around records, meetings, code, notices, accessibility and zoning. It assists staff without pretending to replace their judgment, or the city's systems of record.

How it works

Local by default. Modular by design.

  1. 1
    Install the signed MSI

    One Windows installer brings the desktop shell, bundled Python services, PostgreSQL 17 with PostGIS, and the optional local model runtime.

  2. 2
    Set up the city's workspace

    First run covers the city profile, first administrator, backup location, model download, checksum verification and readiness checks.

  3. 3
    Work inside a human-controlled loop

    Modules organize and draft. Staff review evidence, make decisions, and remain accountable for every public action. Nothing auto-publishes.

Operating principles

Guardrails, not slogans.

01

City-held by default

The default runtime avoids vendor cloud dependencies and outbound telemetry.

02

AI drafts. Humans decide.

No auto-release, auto-denial, auto-redaction, auto-enforcement, or legal determination.

03

Evidence over version labels

Clean-machine checks, source pins, checksums and signed acceptance records drive every maturity claim.

04

Depth before catalog count

Seven modules ship. The other twenty-one are labeled queued, foundation or planned, in public.
